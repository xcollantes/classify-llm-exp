1 · What was tested

Three ways to put a topic label on a piece of text, run over the identical 10-document test set. Two are zero-shot frontier LLMs given the label list and nothing else. The third never sees a prompt: it turns each document into a vector with gemini-embedding-001 at task_type=CLASSIFICATION and hands those vectors to a logistic regression trained on 800 labelled examples.

A fourth arm re-runs the embedding pipeline unchanged except for task_type=SEMANTIC_SIMILARITY. It exists to answer a narrower question: does the task type actually do anything, or is it decoration?

Setup

  • Data. 20 Newsgroups with headers, footers and quoted replies stripped — the metadata that makes this dataset trivially easy. Classes: graphics, baseball, space, electronics. Documents truncated to 2,000 characters.
  • Split. 800 train / 10 test, sampled with seed 67. The LLM arms use zero training examples; only the embedding arms see the training split.
  • Prompt. Identical for both LLMs, temperature 0:
Classify the news article into exactly one of these topics:
graphics, baseball, space, electronics
Reply with the topic word only, nothing else.
Article:
{{document}}
  • Scoring. Exact-match on the label word; a reply that matches no label or several is counted __unknown__ and scored wrong, with the count reported separately.
  • Cost. Measured tokens × list price (Gemini Flash $0.3/ $2.5, GPT-4o mini $0.15/ $0.6, embeddings $0.15 per 1M in/out tokens). Embedding cost counts inference only — training-set embedding is a one-off.

4 · Why the embedding arm works

The embedding classifier is not doing anything clever. With task_type=CLASSIFICATION the vectors already arrange themselves into class-shaped regions before any classifier is fitted — the logistic regression only has to draw the boundaries. 5 · Latency and cost

6 · What this means

  • If you have labelled data, embed it. The embedding classifier is the cheapest arm by a wide margin and competitive on accuracy. Its cost does not grow with prompt length the way an LLM's does, and it has no parsing failure mode.
  • Zero-shot LLMs buy you the cold start. They needed no labelled data at all. That is the whole trade: the embedding arm's 800-document training set is a real prerequisite.
  • Set the task type. It is one keyword argument and it moved accuracy by 0.0% here.

7 · Limitations

  • Four well-separated topics. Harder label sets — fine-grained intent, overlapping categories, class imbalance — compress the gaps and can flip the ordering.
  • Zero-shot only. Few-shot prompting or fine-tuning would likely close some of the LLM arms' gap, at more tokens per call.
  • Single prompt, single run at temperature 0. No prompt-variation study; the LLM numbers carry prompt-sensitivity that the CI does not capture.
  • Latency was measured over the public internet at concurrency 8 and mixes in network and queueing variance.
  • Costs are list prices at the time of the run, not billed amounts.
